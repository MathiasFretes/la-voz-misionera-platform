## Mantenimiento y procedencia de la respuesta

El fallo anterior se reprodujo en una red Docker interna, sin puertos publicados y sin conectar con la API o base activas. El JSON adaptado de Caddy situaba la respuesta 503 después de los manejadores terminales de archivos/proxy. La raíz devolvía 200 incluso sin navegador, redirección, CDN o caché intermediaria.

La candidata reemplaza exclusivamente el bloque del host de LVM por un route con orden explícito: health primero y mantenimiento como manejador restante. Devuelve 503, Retry-After: 120, Cache-Control: no-store, max-age=0 y X-LVM-Maintenance: 1. Se comprobaron cuatro fases de 16 solicitudes cada una: normal, fallo reproducido, corrección y recuperación. El segundo proyecto simulado respondió 200 en las cuatro fases. Se eliminaron los contenedores y la red temporales.

Antes de migrar, la candidata pasó también una matriz real de HTTPS para raíz, Worship, Service y API, incluidos POST. Health siguió disponible. Al concluir la instalación, se restauró exactamente el Caddyfile anterior y sus rutas originales.
